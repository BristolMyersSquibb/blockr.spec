# Assistant as a client extension
Status: draft. Part of [State in JS](Rewrite-1).

This part covers blockr.assistant, whose agent loop moves to the browser as a dock extension. It builds on [Client-drawn dock and extensions](Rewrite-1.2) and on core's commands and scheduler ([Client-owned board state](Rewrite-1.1)).

## Problem

Today's assistant runs its agent loop in the session's R process through ellmer, with 40 tools (`ellmer::tool()` definitions at `fd58655`) that change a running Shiny board. Its mutation tools stage a delta ([`commit_pending()`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/a429c3061348a354834eeb2a5c173f8ff27f7c0b/R/stage-pending.R#L88)), and its `commit` tool applies it through the board's `update()` ([`flush_pending()`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/a429c3061348a354834eeb2a5c173f8ff27f7c0b/R/stage-pending.R#L682)) and waits for the touched blocks to re-evaluate, up to `assistant_commit_timeout_secs`, 30 s by default; a commit can also stop partway, with "the board may be partly updated" ([`tools-commit.R`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/fd5865593fd8b015d00df9238e2e622475c2a9df/R/tools-commit.R#L84-L116)). With the board held by the client ([Client-owned board state](Rewrite-1.1)), there is no R board to stage into, and the assistant's edits and the user's meet in one board.

## What must hold

1. The assistant is a dock extension ([Client-drawn dock and extensions](Rewrite-1.2)) whose edits are deltas through core's commands, applied all or none and marked as its own, so undo keeps its steps apart from the user's ([blockr.core#432](https://github.com/BristolMyersSquibb/blockr.core/issues/432)).
2. An edit reports done only once the blocks it changed, and those downstream of them, are current, with each block's status and conditions.
3. The loop works with the visitor's own credential as with one that R obtains or the deployment provides, and nothing in it changes to switch between them.
4. A turn keeps going while its tab is hidden, until the browser discards the page.

## Proposal

- The agent loop runs in the browser, where the board it edits is, with the commands that core and the extensions register, and requests to R, as its tools, so that it changes what an extension adds, such as blockr.md's document or the DAG's layout, as it changes core's objects ([Board updates](Rewrite-1.1.2#the-front-ends-state-and-attributes)). It reaches the board only through core's JS API, never the DOM, so that it could run in Node on the server the [Roadmap](Roadmap#a-server-of-our-own) considers.
- Two libraries run such a loop in a browser, and a spike chooses between them (Work): the AI SDK, `ai` with a provider package such as `@ai-sdk/anthropic`, and pi, `@earendil-works/pi-agent-core` with `@earendil-works/pi-ai`, while a provider's own SDK would leave the loop to us. The spike builds the edit tool, one request to R and compaction on each, and keeps the library that does the following with less code of our own, the smaller bundle breaking a tie: it meets What must hold 1 to 4, streams a turn and stops it when the user does, takes the JSON Schemas that core and the extensions register as tool schemas unchanged, goes on with a thread once its board is saved and opened again, and runs under Vitest on happy-dom with the model faked.
- The assistant pays for nothing but the model provider's tokens for now, so it uses no hosted service, such as Vercel's AI Gateway (notes) or assistant-ui's Assistant Cloud.
- The assistant ships the `llm_model` board option, which core defines today ([R/board-option.R#L666-L751](https://github.com/BristolMyersSquibb/blockr.core/blob/da3fcb499549043d02d0300e05c7161f528c8729/R/board-option.R#L666-L751)) and only the assistant reads, and defines it in the client as every package defines the board options it ships ([Board objects](Rewrite-1.1.1#board-options)).
- One edit tool takes a whole delta and applies it as one undoable step, rather than one tool per command, as Anthropic's guidance argues: "More tools don't always lead to better outcomes" ([Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)).
- The edit tool evaluates the blocks it changed and everything downstream of them, those no panel shows included, in a one-time evaluation ([Evaluation in the client](Rewrite-1.1.10#demand)), and returns once they are current, with each block's status and conditions, so that it sees every failure it caused, and a block the user edits meanwhile at its newer revision.
- A reply streams in the extension's memory and enters its thread, in the assistant's extension state, as one finished message, since a delta per token would reach every follower, as a delta per keystroke would ([Board updates](Rewrite-1.1.2#undo)). Every change to a thread carries an origin of its own, whoever wrote the message, so that neither the user's undo nor the assistant's takes a message back.
- While a turn runs, the assistant holds a Web Lock named for its tab, since Chrome freezes a background tab, which stops its tasks and fails its WebSockets, unless it holds one ([workadventure#6740](https://github.com/workadventure/workadventure/pull/6740)). Nothing on a turn's path waits on chained timers, which a tab hidden for five minutes runs once a minute, or on animation frames, which a hidden tab never runs ([timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)).
- The extension loads its loop, its provider code and its chat UI with a dynamic import when its panel first opens, since the loop and provider code alone weigh 116 to 205 KB gzipped (notes), which a board whose panel stays closed never needs.
- The loop takes its credential through one function of the library, a key or a token fetched for each request, `authToken` in the AI SDK's Anthropic provider and `getApiKey` in pi, so where it comes from stays open (below). What a visitor can take is no downside of the client: any visitor who can use the assistant can take a credential it uses, today as after the switch, since a visitor runs R through a block that takes their code, as core's subset block takes its `subset` and `select` ([R/transform-subset.R#L29-L31](https://github.com/BristolMyersSquibb/blockr.core/blob/da3fcb499549043d02d0300e05c7161f528c8729/R/transform-subset.R#L29-L31)), and through the assistant, which writes such code when asked and reads the block's output. A credential in the browser only makes that visible. Limiting it stays the deployment's job ([State in JS](Rewrite-1#proposal)), which matters most for an app on the public internet, whose visitors are anyone.

## Open questions

- Whether an answer that needs a number adds a block, so that every number the assistant reports is in the exported code, or the assistant may run R outside blocks.
- How the browser gets its credential: the visitor's own key, a token R obtains for the visitor, a short-lived token R mints, or a key of the app's that R hands over, with the proxy in R only for a provider that visitors' browsers cannot reach (notes), or a key that the server the [Roadmap](Roadmap#a-server-of-our-own) considers holds out of R's reach. It blocks the last Work item, not the loop (What must hold 3), and choosing which of these the assistant supports first settles it.

## Work

- Spike the agent loop on the AI SDK and on pi, and choose between them by the conditions in the Proposal, in blockr.assistant
- Rebuild the assistant as a client extension on the library the spike chose, with its agent loop in the browser, in blockr.assistant
- Give the browser its credential as the open question settles, with the stateless proxy in R where a provider needs it, in blockr.assistant

The 40 tool definitions at `fd58655`, by file: `tools-read.R` 11, `tools-view.R` 11, `tools-mutation.R` 9, `tools-extension.R` 3, `tools-commit.R` 2, `tools-options.R` 2, `skills-invoke.R` 1, `tools-typed.R` 1.

Tool schemas can come from the registered commands, the schemas of the front-end's state and the block arg specs, a JSON Schema subset that blockr.ai already binds through `ellmer::type_from_schema()`. The AI SDK's `jsonSchema()` takes such a schema as it is, while pi types its tools with TypeBox, so the spike checks that such a schema passes pi's validation unchanged. Both official SDKs refuse to run in a browser without `dangerouslyAllowBrowser: true`, a key there being readable by every visitor. A proxy in R, which forwards the provider's own API with the credential added, cannot stream over HTTP, since httpuv takes a response body only whole, as "A string (or raw vector)", so streamed tokens would travel over the websocket and pause while R evaluates, and since R runs one request at a time ([Wire protocol](Rewrite-1.1.9#one-request-at-a-time)), it needs a message of its own outside that queue, or a model call holds evaluation for its whole length.

The pi project moved from `badlogic/pi-mono` to [earendil-works/pi](https://github.com/earendil-works/pi) in spring 2026, and its npm packages from the now deprecated `@mariozechner/*` to `@earendil-works/*`. Its `pi-ai` "supports browser environments", except for Amazon Bedrock and the OAuth login flows ([README](https://github.com/earendil-works/pi/blob/e3da248ea9100a3b5d53f9c701b6a47ef7f58d6e/packages/ai/README.md#browser-usage)), and reaches a proxy that speaks a provider's API as a provider made with `createProvider()`, whose models name the proxy as their `baseUrl` ([README](https://github.com/earendil-works/pi/blob/e3da248ea9100a3b5d53f9c701b6a47ef7f58d6e/packages/ai/README.md#createprovider)). Its `pi-agent-core` adds the loop, with steering and follow-up queues, `beforeToolCall` and `afterToolCall`, `transformContext` "for pruning, compaction" and a replaceable `streamFn`, for which `streamProxy()` serves "browser apps that proxy through a backend" ([README](https://github.com/earendil-works/pi/blob/e3da248ea9100a3b5d53f9c701b6a47ef7f58d6e/packages/agent/README.md#proxy-usage)), posting to a server of pi's own at `/api/stream` that answers in pi's events ([proxy.ts#L146-L150](https://github.com/earendil-works/pi/blob/e3da248ea9100a3b5d53f9c701b6a47ef7f58d6e/packages/agent/src/proxy.ts#L146-L150)), which the proxy here, a pass-through of the provider's API, is not. Sitegeist, a Chrome side-panel agent by pi's author, was built on both and on `pi-web-ui` ([badlogic/sitegeist](https://github.com/badlogic/sitegeist)), whose web components left the repo after 0.75.3 in May 2026, so pi brings no UI. The AI SDK runs a `ToolLoopAgent` in the page behind `useChat` through `DirectChatTransport` ([reference](https://ai-sdk.dev/docs/reference/ai-sdk-ui/direct-chat-transport)), and its providers take `baseURL`, `headers` and `fetch` ([Anthropic provider](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic)), while a model named by a bare id goes to Vercel's AI Gateway, since "By default, the global provider is set to the Vercel AI Gateway" ([provider management](https://ai-sdk.dev/docs/ai-sdk-core/provider-management)). The chat UI of `@assistant-ui/react` runs on either loop through its custom runtimes ([LocalRuntime](https://www.assistant-ui.com/docs/runtimes/custom/local-runtime)).

Neither library summarizes a thread: pi leaves compaction to `transformContext`, and the AI SDK's guide prunes through `prepareStep` and `pruneMessages` without a model call ([guide](https://ai-sdk.dev/cookbook/guides/agent-context-compaction)). The summarizing compaction of pi's CLI is in `pi-coding-agent`, under [`src/core/compaction`](https://github.com/earendil-works/pi/tree/e3da248ea9100a3b5d53f9c701b6a47ef7f58d6e/packages/coding-agent/src/core/compaction), MIT and not exported. Today's assistant does its compaction, its threads and its skills itself, in [`ext-compact.R`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/fd5865593fd8b015d00df9238e2e622475c2a9df/R/ext-compact.R), [`ext-history.R`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/fd5865593fd8b015d00df9238e2e622475c2a9df/R/ext-history.R) and the `skills-*.R` files, which are ported whichever library runs the loop.

Measured on 2026-10-31, a minimal agent with one tool and the Anthropic provider, bundled with esbuild 0.25.12 as minified ESM for the browser and gzipped at level 9, weighs 205 KB with the AI SDK (912 KB minified, of which zod 4.6.7 takes 443 KB and the unused AI Gateway client 71 KB) and 116 KB with pi (435 KB minified, of which `@anthropic-ai/sdk` takes 181 KB and TypeBox 142 KB). The Anthropic SDK alone weighs 76 KB, and a client that ships zod anyway shares it with the AI SDK.

A hidden page runs timers once a second, a chain of five or more once a minute after five minutes hidden, and animation frames not at all ([timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)). Chrome freezes CPU-intensive background tabs on Energy Saver since Chrome 133 ([freezing](https://developer.chrome.com/blog/freezing-on-energy-saver)). In a field trial, reproduced with Chrome 153, it freezes every background tab but the five most recently used and unfreezes each for 5 s a minute, and a frozen page's WebSockets fail at the first unfreeze, while a tab holding a Web Lock stayed unfrozen with its socket open for 9 minutes ([workadventure#6740](https://github.com/workadventure/workadventure/pull/6740)). The lock is named for the tab, since a tab waiting for another tab's lock is not protected (same PR). From Chrome 155 the enterprise policy `BackgroundTabFreezingEnabled` governs that freezing, which is on unless the policy or the user turns it off, and exempts a page holding a Web Lock ([policy](https://github.com/chromium/chromium/blob/7a3c8d1b05ccf31dc16b9ad3f88720485e0cddf6/components/policy/resources/templates/policy_definitions/Miscellaneous/BackgroundTabFreezingEnabled.yaml)). Memory Saver discards an inactive tab, which reloads without its state, unless its URL matches the enterprise policy `TabDiscardingExceptions`, which exempts it from freezing too ([policy](https://github.com/chromium/chromium/blob/7a3c8d1b05ccf31dc16b9ad3f88720485e0cddf6/components/policy/resources/templates/policy_definitions/Miscellaneous/TabDiscardingExceptions.yaml)).

Calls from the browser leave from the visitor's machine, where a company network may block the provider's domain or buffer the stream, and an endpoint private to the server's network is out of reach, as is a provider that refuses cross-origin requests, which is what the proxy in R is for. A stream that must travel over the websocket goes through an AI SDK provider's `fetch` or pi's `streamFn`. A request that R loses to a new session is rejected rather than sent again ([Wire protocol](Rewrite-1.1.9#evaluating-a-block)), so the tool hands the failure to the model.

Connect's viewer OAuth integrations, such as for Azure, AWS and Databricks, give R a visitor's access token through `connectapi::get_oauth_credentials()` and the session's `Posit-Connect-User-Session-Token` header, and "OAuth refresh tokens are never returned by Connect" ([Connect](https://docs.posit.co/connect/user/oauth-integrations/)). Anthropic's Workload Identity Federation exchanges a JWT from an identity provider, such as Entra ID, for a Claude token that acts as a service account and lasts 60 seconds to 24 hours, one hour by default ([docs](https://platform.claude.com/docs/en/manage-claude/workload-identity-federation)), which a visitor who runs R can mint as well, so it limits how long a copy works rather than who can get one. OpenAI's and Gemini's short-lived tokens are made for their realtime and live APIs ([OpenAI](https://developers.openai.com/api/docs/guides/realtime-webrtc), [Gemini](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens)).
