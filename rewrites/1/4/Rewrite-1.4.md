# Assistant as a client extension
Status: draft. Part of [State in JS](Rewrite-1).

This part covers blockr.assistant, which becomes a plugin whose agent loop runs in the browser.
It builds on the plugins, commands, scheduler and requests of [Client-owned board state](Rewrite-1.1), on the dock's commands for the views it arranges today ([Client-drawn dock](Rewrite-1.2)), and on blockr.ui's design system for its look ([UI kit and design system for the client](Rewrite-1.7)).
Where its calls to a model go is [Model access](Rewrite-1.4.1)'s, its tools are [The assistant's tools](Rewrite-1.4.2)'s, its threads are [The assistant's state](Rewrite-1.4.3)'s, and its chat is [The assistant's chat](Rewrite-1.4.4)'s.

## Problem

Today's assistant runs its agent loop in the session's R process through ellmer, with 40 tools (`ellmer::tool()` definitions at `fd58655`) that change a running Shiny board.
Its mutation tools stage a delta ([`commit_pending()`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/a429c3061348a354834eeb2a5c173f8ff27f7c0b/R/stage-pending.R#L88)), and its `commit` tool applies it through the board's `update()` ([`flush_pending()`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/a429c3061348a354834eeb2a5c173f8ff27f7c0b/R/stage-pending.R#L682)) and waits for the touched blocks to re-evaluate, up to `assistant_commit_timeout_secs`, 30 s by default; a commit can also stop partway, with "the board may be partly updated" ([`tools-commit.R`](https://github.com/BristolMyersSquibb/blockr.assistant/blob/fd5865593fd8b015d00df9238e2e622475c2a9df/R/tools-commit.R#L84-L116)).
With the board held by the client ([Client-owned board state](Rewrite-1.1)), there is no R board to stage into, and the assistant's edits and the user's meet in one board.

## What must hold

1. The assistant is a plugin, which works under every frontend ([Plugins](Rewrite-1.1.12#what-must-hold)), and whose edits go through core's command registry, each applied all or none and marked as its own, so that undo keeps its steps apart from the user's ([Board updates](Rewrite-1.1.2#what-must-hold)).
2. An edit reports done only once the blocks it changed, and those downstream of them, are current, with each block's status and conditions.
3. The loop works with every place that its calls can go and every way to authenticate them that [Model access](Rewrite-1.4.1) gives, and nothing in it changes to switch between them.
4. A turn keeps going while the assistant's panel is closed or its tab is hidden, until the browser discards the page.
5. What blockr.assistant offers today carries over, but for what Today drops with its reason.
6. Boards saved with today's assistant open with its threads, as condition 4 of [State in JS](Rewrite-1#what-must-hold) asks.

## Proposal

- The assistant is a plugin of one class, `blockr.assistant-assistant_plugin`, named Assistant, which blockr.assistant's startup module registers ([Plugins](Rewrite-1.1.12#a-plugin)).
  Its state holds the threads ([The assistant's state](Rewrite-1.4.3)), its `ui` draws the chat in whatever place the frontend gives it, and its `start` runs each turn, so that a turn goes on once the panel closes ([Plugins](Rewrite-1.1.12#running-a-plugin)).
  Its method of `plugin_requests()` gives what needs R or the server's files: the summary of a block's result through `describe_result()`, the evaluation of R code that the model writes, and the list of skills and the text of each ([Plugins](Rewrite-1.1.12#a-plugins-requests)).
  An app script makes it with `new_assistant_plugin()`, which takes the threads of a board that the script builds.
- The agent loop runs in the browser, where the board it edits is, with the commands that core and the packages of other plugins register, and requests to R, as its tools, so that it changes another plugin's state, such as blockr.md's document or the DAG's positions, through that plugin's commands or core's `blockr.core-set_plugin_state`, as it changes core's objects through core's commands ([Plugins](Rewrite-1.1.12#a-plugins-state)).
  It reaches the board only through `CoreApi`, never the DOM, so that it could run in Node on the server the [Roadmap](Roadmap#a-server-of-our-own) considers.
- The tools read the board, the block registry and each block's status in the browser, and send R a request only for what needs R: a block's result, which R describes through `describe_result()`, the model's own R code, and the skills ([The assistant's tools](Rewrite-1.4.2)).
  So a package that teaches the model about a class of results keeps giving a method of that generic in R, as blockr.sandbox does for its composer tables.
- The model may run R outside blocks, as `inspect_results` lets it today, on the results of the blocks that it names, so that a number it reports from there is in no exported script, as today, while R refuses that request on a locked board ([The assistant's tools](Rewrite-1.4.2#the-requests-in-r)).
- Two libraries run such a loop in a browser, and a spike chooses between them (Work): the AI SDK, `ai` with a provider package such as `@ai-sdk/anthropic`, and pi, `@earendil-works/pi-agent-core` with `@earendil-works/pi-ai`, while a provider's own SDK would leave the loop to us.
  The spike builds the edit tool, one request to R and compaction on each, with OpenAI's provider, which both apps that use the assistant today chat through (Today), and with Anthropic's.
  It keeps the library that does the following with less code of our own, the smaller bundle breaking a tie: it meets What must hold 1 to 4, streams a turn and stops it when the user does, takes the JSON Schemas that core and other packages register as tool schemas unchanged, goes on with a thread once its board is saved and opened again, and runs under Vitest on happy-dom with the model faked.
- The assistant needs no hosted service: a deployment may send its calls through a gateway, such as OpenRouter or Vercel's AI Gateway ([Model access](Rewrite-1.4.1)), but no part of the assistant runs on one, such as assistant-ui's Assistant Cloud.
  The AI SDK reaches Vercel's AI Gateway only where a deployment names it, never through a model named by a bare id (notes).
- The board options `llm_model`, which core defines today, and `chat_compact_tokens` and `chat_compact_keep` go, with the blockr option `chat_function`, since all four were shaped for ellmer's chat functions (Today).
  Who picks the model is [Model access](Rewrite-1.4.1)'s, and a setting that a later need brings goes in the assistant's state first ([Places the dock offers plugins](Rewrite-1.2.4#settings)).
- One edit tool takes a list of commands, which core plans in order, each on the board that the commands before it leave, and applies as one undo step of the assistant, and it returns once the blocks it changed and those downstream of them are current, through one one-time evaluation ([The assistant's tools](Rewrite-1.4.2#the-edit-tool)).
  So one edit can add a block, link it and show its panel, while each change goes through the command that keeps it valid and refuses what a lock fixes.
  One tool takes every command, rather than one tool per command, as Anthropic's guidance argues: "More tools don't always lead to better outcomes" ([Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)).
- A reply streams in the plugin's memory and enters its thread as one finished message, through the assistant's own commands, which take no undo step, so that no undo takes a message back ([The assistant's state](Rewrite-1.4.3#commands)).
- While a turn runs, the assistant holds a Web Lock named for its tab, since Chrome freezes a background tab, which stops its tasks and fails its WebSockets, unless it holds one ([workadventure#6740](https://github.com/workadventure/workadventure/pull/6740)).
  Nothing on a turn's path waits on chained timers, which a tab hidden for five minutes runs once a minute, or on animation frames, which a hidden tab never runs ([timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)).
- The plugin loads its loop and its provider code with a dynamic import as the first turn starts, since they weigh 116 to 205 KB gzipped (notes), which a page where nobody asks the assistant anything never needs.
  A panel that shows is no sign of that, since a board's default view in the dock holds every plugin's panel on its left rail ([Places the dock offers plugins](Rewrite-1.2.4#a-plugins-panel)).
- The loop takes its credential through one function that the library calls for each request, a `fetch` of its own in an AI SDK provider and `getApiKey` in pi, so that every way to authenticate that [Model access](Rewrite-1.4.1) gives feeds it, and the loop knows none of them.
