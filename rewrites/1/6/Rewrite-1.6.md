# Session management as a storage plugin
Status: review. Part of [State in JS](Rewrite-1).

This part covers blockr.session, whose session management becomes a storage plugin that makes its storage calls from the browser.
It builds on core's storage plugins, `storage.load()` and requests ([Plugins](Rewrite-1.1.12#storage), [Drawing the board](Rewrite-1.1.8#starting-the-page)), and on the dock's navbar, which draws the plugin's controls ([The dock's navbar](Rewrite-1.2.5#the-storage-plugins-controls)).

## Problem

The blockr.session package opens, saves, versions and shares boards from `manage_project()`, which takes the place of core's `preserve_board` plugin.
Its storage sits behind the rack layer, S3 generics over pins ([R/rack.R#L154-L540](https://github.com/BristolMyersSquibb/blockr.session/blob/66d950549a905066a2860c1d39da1cf6cf320bc8/R/rack.R#L154-L540)), and on Connect each visitor saves under their own account ([R/backend.R#L1-L15](https://github.com/BristolMyersSquibb/blockr.session/blob/66d950549a905066a2860c1d39da1cf6cf320bc8/R/backend.R#L1-L15)).
A Shiny board cannot be replaced in place, so opening another board or a new one reloads the page with `session$reload()` ([R/server.R#L235-L247](https://github.com/BristolMyersSquibb/blockr.session/blob/66d950549a905066a2860c1d39da1cf6cf320bc8/R/server.R#L235-L247)).
After the reload, `rack_loader()`, a `board_loader()` for `serve()`, builds the board that the URL names, and it fetches and deserializes the record twice for each page: once at the page's GET and once as the websocket connects ([R/server.R#L1179-L1289](https://github.com/BristolMyersSquibb/blockr.session/blob/66d950549a905066a2860c1d39da1cf6cf320bc8/R/server.R#L1179-L1289)).
With the board held by the client ([Client-owned board state](Rewrite-1.1)), R is needed only to exchange the visitor's credential, which no one but the content's process receives.
The rest is calls to an API.

## What must hold

1. What blockr.session offers today carries over, but for what Today drops with its reason: opening, saving, versioning, sharing, tagging, downloading, uploading and deleting boards, from a storage plugin whose controls every frontend draws ([Plugins](Rewrite-1.1.12#storage)), and with no page reload.
2. The browser drives every storage call: it calls Connect itself, and any other backend through one storage API, so that no save or listing on Connect or on a deployment's own service waits on R, and neither does opening a record that the new stack saved there.
   R takes part only where nothing else can: once per page, it exchanges the visitor's session token, which only the content's process receives, for a key, and, for setting up and testing, it serves the storage API on a pins folder of its own disk.
3. A URL names a record by its key, its owner and its version, in `id`, `user` and `version` as today, and a link made today still opens the record that it names, through `board_name` too, once that record is converted (condition 6).
4. Saving a board that no record holds creates a record under a key that the user picks, and never adds a version to another record.
5. Outside the load lock, unsaved work survives a crash of R's process, of the page or of the browser, with no blockr option to set, and the same browser offers it again to the same user.
6. The plugin converts nothing that today's stack saved, and refuses a record or a file of today's stack with core's error ([The conversion and the migration notes](Rewrite-1.8.3#who-converts)).
   A record that blockr.session stored today opens once blockr.convert's `convert_file()` has converted it.

## Proposal

- Session management is a storage plugin of one class, `blockr.session-session_plugin`, named Session management, which blockr.session lists in its `._BLOCKR_MODULES_` with its module and its constructor, `new_session_plugin()` ([Plugins](Rewrite-1.1.12#a-plugin)).
  Its class in R is `c("session_plugin", "storage_plugin", "plugin")` ([Plugins](Rewrite-1.1.12#plugin-classes)).
  It keeps no state in the board, so its constructor takes no args ([Plugins](Rewrite-1.1.12#storage)).
  It runs by default wherever blockr.session is installed, so `manage_project()` goes, and a script that keeps core's storage plugin leaves blockr.session's out of the rows of `plugins` ([Plugins](Rewrite-1.1.12#storage)).
  Its controls take the place of core's Save and Open, which save a download and open an upload.
  Its method of `plugin_requests()` gives what needs R: a request for each operation of R's folder and the once-per-page request, which names the backend and, on Connect, exchanges the visitor's session token.
- Its storage controls are those of today's piece of the navbar, in today's order: a workflows menu named after the record's key, a button for the drafts, the save status and a Save menu, followed by a status with the initials of the user whom the backend knows, while dialogs of the plugin's own hold what the controls cannot, such as the records with their search, sharing and the key chooser ([The controls and dialogs](Rewrite-1.6.3)).
  The controls call a record a workflow, as today's do, since "workflow" is the user's word for their board ([Glossary](Glossary)).
- A URL that names a record opens it through the plugin's `storage.load()`, before anything is drawn, and a record that the user opens later opens through `core.store.open()`, with no reload, so that `rack_loader()` goes ([The controls and dialogs](Rewrite-1.6.3#opening)).
  "New workflow" opens the board that R sent, with no reload ([The controls and dialogs](Rewrite-1.6.3#new)).
- Save adds a version to the record that the plugin opened, unless nothing changed, while a board that no record holds asks for a key at its first save, and a record's key is fixed once the user picks it ([The controls and dialogs](Rewrite-1.6.3#saving), [The storage API](Rewrite-1.6.1#records-and-versions)).
  Where the user may only open the record, as one whom its owner shared it with, Save asks for a key as "Save as new workflow…" does ([The controls and dialogs](Rewrite-1.6.3#saving)).
- The rack layer becomes a storage API of named operations, with JSON args and replies, which the plugin calls from the browser, so that a service of a deployment's own, in any language, puts a database, S3 or other storage behind the plugin, where the blockr option `session_mgmt_backend` names that service by its URL ([The storage API](Rewrite-1.6.1)).
  Without that blockr option, the plugin uses Connect where the visitor has a key, R's folder where R runs off Connect, and no backend otherwise ([The storage API](Rewrite-1.6.1#choosing-the-backend)).
- On Connect, the plugin calls Connect's API itself, with a key that R exchanges once per page for the visitor's session token, and writes and reads the pins of records itself, today's included, so that no save or listing waits on R, and the app's own Connect key goes ([Connect from the browser](Rewrite-1.6.2)).
  The plugin offers what the key's role may do, and a key holds its visitor's role unless the app's integration caps keys lower, so that on a key with Connect's Viewer role, which by default may create no content, it opens the records shared with the visitor and saves downloads ([Connect from the browser](Rewrite-1.6.2#what-a-visitors-role-allows)).
- For setting up and testing, R serves the storage API on a pins folder of its own disk, answering each operation as one of the plugin's requests ([The storage API](Rewrite-1.6.1#rs-folder)).
- Where the plugin has no backend, its controls save a download, open an upload and start a new board, with a status that says why no records show ([The controls and dialogs](Rewrite-1.6.3#without-a-backend)).
- The plugin writes drafts of unsaved work to the browser's own storage in every app, with no blockr option to set, and the same browser offers them again to the same user, at no cost to a backend ([Drafts in the browser](Rewrite-1.6.4)).
- The plugin converts nothing that today's stack saved, and refuses its records and files with core's error ([Records, links and app scripts across the switch](Rewrite-1.6.5)).
  A deployment converts the records that it keeps with blockr.convert's `convert_file()`, after which the links made today open them.
