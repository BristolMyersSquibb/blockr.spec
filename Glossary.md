# Glossary
Revised on 2026-10-30.

Every page, spec and issue of the rewrites uses these names in these senses only, and a new term is agreed before it appears on a page. The terms outlast the rewrite that brought them in, so they live here rather than on a rewrite's root, and [State in JS](Rewrite-1) brought in these.

| Term | Means |
|---|---|
| Block class | A value made by `new_block_class()`, defined once and held by the block registry under its registry id, through whose fields R evaluates every block of the class ([Block classes in R](Rewrite-1.1.5#the-block-class)) |
| Block | One instance of a block class, which the board holds as `{ registry_id, state, name }` ([Blocks](Rewrite-1.1.1#blocks)). R makes an R block, with the class's constructor, only while it builds a board. A block is never a block class, which is always called one |
| Block state | A block's values for the formals of its class's `expr`, its state args, such as a head block's `n`, which a user sets through the block's UI and the board holds as the block's `state`. It is one of the two sorts of input a block has, beside its data inputs ([Block classes in R](Rewrite-1.1.5#the-block-class)) |
| Data input | One of the inputs a block's class declares in `inputs`, such as a head block's `data`, which a link binds to an upstream block's result. It is one of the two sorts of input a block has, beside its block state ([Block classes in R](Rewrite-1.1.5#the-block-class)) |
| Block registry | R's registry of block classes, filled by `register_block()`, whose entries R sends the client |
| Registry id | A block class's id in the block registry, such as `blockr.core-head_block` |
| Block expression | The R expression R evaluates for a block, whose result R keeps under the block's id, and an exported script holds for it, without the assignment to the block's id that the script adds, which interpolation makes from what its class's `expr` returns: with the upstream blocks' ids in place of the placeholders of a `blockr_expr`, and otherwise as a function of the block's data inputs called with those ids ([Block classes in R](Rewrite-1.1.5#expressions)) |
| Placeholder | A data input written as `.(data)`, or a variadic block's inputs as `...`, in what `bbquote()` returns, or as another class that inherits from `blockr_expr` writes them, which interpolation replaces with the upstream blocks' ids ([Block classes in R](Rewrite-1.1.5#expressions)) |
| Interpolation | Filling in placeholders such that we get a quoted expression that can be evaluated in the context of data, the block expression: R calls a class's `expr` with the block state, and the generic `interpolate()` turns what `expr` returns into the block expression, dispatching on its class ([Block classes in R](Rewrite-1.1.5#expressions)) |
| Command registry | The client's registry of commands ([Board updates](Rewrite-1.1.2#commands)) |
| Board | The client's board, the JSON object the store holds |
| R board | The R object that an app script's constructors build, or that `blockr_deser()` builds from a file of today's stack, and that R drops once it has the board's JSON |
| Board option | An option the user sees and changes while the app runs, an `Option` in the client, with an `id`, `label`, `category`, `schema` and `ui`, which the package that ships it defines in the client, and whose value the board holds under its id ([Options](Rewrite-1.1.1#options)) |
| Blockr option | A value fixed when an app starts or is deployed, which `blockr_option()` reads from an R option `blockr.<name>` or an environment variable `BLOCKR_<NAME>`, and which the board never holds ([Defining a board in R](Rewrite-1.1.3#blockr-options)) |
| Extension state | What an extension carries, as a block carries its state, such as the DAG's positions, blockr.md's document or the assistant's threads, which the front-end's state holds, since an extension extends a front-end, as the dock keeps it under `extensions` by each extension's id, and which is saved and undone with the board and open to external control ([Board updates](Rewrite-1.1.2#the-front-ends-state-and-attributes)) |
| Front-end state | What the board's front-end keeps: its own, such as the dock's views, their layouts and which view is active, and its extensions' state, each key registered with the store at its path, by whoever owns it, and saved and undone with the board and open to external control, as the assistant creates, changes and removes views today ([Board updates](Rewrite-1.1.2#the-front-ends-state-and-attributes)) |
| Attribute | A value kept on a block that is not its state, such as `visible`, which sections of its card show: it says how the block shows, never what it computes, so it bumps no revision, and it is saved with the board and open to external control. Core defines a block's attributes, and a front-end may have attributes of its own beside its state ([Blocks](Rewrite-1.1.1#blocks)) |
| External control | Setting a block's state or attributes, an extension's state or the front-end's state from outside what owns it, as a drill sets a cohort filter's condition, or as the assistant edits a block, arranges the dock's views or moves the DAG's positions, through the commands that set them, which every block, extension and front-end is open to ([Board updates](Rewrite-1.1.2#commands)) |
| Front-end | The module that draws a board, which a package declares in R under a name for a board class, giving it an id such as `blockr.dock-dock`, and which a board names in its `front_end.id`, as R picks it by the board's class ([Front-ends and extension points](Rewrite-1.1.8#registering-a-front-end)) |
| Startup module | The one module a package may declare in R for what has to run before anything mounts, which core initializes with `CoreApi`, one package at a time in the order of their R dependencies, before the front-end mounts and before the store opens a board ([UI modules in JS](Rewrite-1.1.7#startup-modules)) |
| Output | An S3 object of an output class, which the class's coercion makes from one result and R sends as JSON, naming the renderer that draws it ([Block classes in R](Rewrite-1.1.5#outputs)) |
| Output class | An S3 class of outputs, whose class vector ends in `block_output`, such as `table_output`, which the package that defines it gives a constructor, `new_table_output()`, a coercion that makes an output from a result, `as_table_output()`, and a contract that its renderers are written against, the TypeScript types of its outputs and of their parameters with fixtures, which a block class names by its coercion, and which another package extends with a subclass ([Block classes in R](Rewrite-1.1.5#outputs)) |
| Renderer | A module that draws the outputs of one output class or a board option's value, which a package declares in R, and of which R picks one for each output class and each board option, naming in each output the one for the most specific class that has one ([Front-ends and extension points](Rewrite-1.1.8#renderers)) |
| Lock | What an app fixes when it starts, and R holds in what it runs so that no client can loosen it: a locked board loads no other board and keeps everything core keeps in it, and every block keeps its opening state but those whose inputs show, as core's attribute `visible` says on the board the app script built, while a front-end may lock more of what it alone governs, such as the dock the arrangement of its panels ([Wire protocol](Rewrite-1.1.9#locked-boards)) |
| Request | What the client asks R for an answer, rather than for a block's result: a function that a block class, a board option or an extension registers in R, which R resolves by that object's id ([Wire protocol](Rewrite-1.1.9#requests)) |
| Demand | What an owner asks the scheduler to keep evaluated, a set of blocks or a function of the board, until it releases it. The scheduler evaluates every demanded block and what feeds it, while a one-time evaluation brings some blocks up to date once ([Evaluation in the client](Rewrite-1.1.10#demand)) |
| One-time evaluation | What brings some blocks up to date once, without keeping them evaluated, and resolves with their statuses, or, given parameters, runs them even where they are current ([Evaluation in the client](Rewrite-1.1.10#demand)) |
| Parameter | A value that a request, an output request or a one-time evaluation passes besides the block's state, such as the column whose values a dropdown lists, a save's `save` or the page a table output shows, which `expr` never sees and the board never holds ([Block classes in R](Rewrite-1.1.5#requests)) |
| Evaluation priority | A number that every demand and one-time evaluation carries, 0 by default, by which the scheduler orders evaluations, and where an evaluation below 0 gives way to whatever waits behind it ([Evaluation in the client](Rewrite-1.1.10#demand)) |
| Recipe | What an evaluation request carries for a block: its registry id, its state, and its inputs as upstream blocks and revisions, in the order of its class's inputs, from which R builds the block expression ([Wire protocol](Rewrite-1.1.9#evaluating-a-block)) |
| Revision | A block's number in the scheduler, which goes up whenever the block's recipe changes or something invalidates it, never goes back within the page, and names the block's result in R, unlike a version, which is always a package's, the protocol's, a file format's or a saved board's ([Evaluation in the client](Rewrite-1.1.10#revisions)) |
| Edit id | What the store keeps for each block and for each entry or value of the front-end's state, which only their own edits change, and which a delta names so that the store refuses it where another edit came first ([Board updates](Rewrite-1.1.2#deltas)) |
